## 3. 企业需求文档

### 3.1 基本信息

| 项目 | 内容 |
|---|---|

| 技术负责人 | 陈工 |
| 安全负责人 | 顾晴 |
| 目标版本 | 0.0.7 |

### 3.2 业务背景

Agent 试点涉及客服、销售、财务、技术和产品协作。员工需要按姓名、部门、岗位或技能找到合适协作者。现有模拟名单散落在消息中，名称和技能格式不统一。项目只做培训环境的虚构目录，验证数据模型与搜索能力，不导入真实员工信息。

### 3.3 用户故事

> 作为 Agent 试点目录维护人，  
> 我希望新增、查询、更新和删除模拟联系人，并跨进程保存，  
> 从而快速找到具备所需技能的协作者。

### 3.4 数据契约

```json
{
  "schema_version": 1,
  "revision": 4,
  "owner": {
    "employee_id": "E70007",
    "department": "客户服务部"
  },
  "contacts": [
    {
      "contact_id": "C2",
      "name": "李梅",
      "department": "技术部",
      "role": "高级 AI 工程师",
      "email": "limei@example.test",
      "skills": ["python", "rag"]
    }
  ]
}
```

### 3.5 字段规则

| 字段 | 规则 |
|---|---|
| contact_id | C 开头、非空、目录唯一 |
| name | 折叠空白、非空 |
| department | 五部门白名单，研发部→技术部 |
| role | 折叠空白、非空 |
| email | 小写、一个@、两侧非空、域名含点、目录唯一 |
| skills | 逗号输入、清理、小写、去重、排序 |

### 3.6 业务规则

**新增**：编号和邮箱都唯一才写入。失败不增加 revision。

**查看**：按部门、姓名、编号排序，不修改主列表。

**搜索**：关键词小写后，在姓名、部门、岗位、邮箱和技能拼接文本中做子串匹配；空关键词返回空。

**更新**：今日 CLI 更新岗位；业务函数允许姓名、部门、岗位、邮箱、技能，未知字段忽略。邮箱更新必须排除自己并检查其他联系人。

**删除**：按编号硬删除；当前没有审计，生产需软删除。

**统计**：总人数、各部门人数、唯一技能排序。

### 3.7 验收标准

**AC-01 首次初始化**：E70007/客服部保存 owner，revision1。

**AC-02 新增治理**：研发部保存技术部，邮箱小写，技能重复去除。

**AC-03 双唯一**：重复编号或重复邮箱拒绝，不增加 revision。

**AC-04 排序**：技术部李梅显示在销售部王芳之前。

**AC-05 搜索**：PYTHON 命中李梅；“销售”命中王芳；空词0。

**AC-06 更新**：C2 岗位更新后 revision+1；相同值不变。

**AC-07 删除复用**：删除 C1 后可用 C1 与新邮箱新增周宁。

**AC-08 恢复**：第二进程恢复 owner 和2名联系人，不再询问身份。

**AC-09 发布**：zip 无 nexus_contacts.json；解压后首次和恢复均成功。

### 3.8 非功能要求

- 仅模拟姓名与 `.test` 邮箱。
- 终端不输出未治理原始值。
- JSON UTF-8、稳定键、末尾换行。
- 所有测试使用临时目录。
- 发布包三项白名单。

## 5. 第一周知识复习课堂笔记

### 5.1 类型选择

编号和邮箱用 str；revision用 int；联系人列表用 list；联系人记录用 dict；技能唯一汇总用 set；固定部门用 tuple；校验结果用 bool。

### 5.2 字符串治理

`strip/split/join/lower/upper/replace/count/find` 都必须按字段语义使用。邮箱统一 lower，姓名不强制 lower，编号删除空格。

### 5.3 条件与循环

条件表达规则，while处理未知重试，for遍历联系人，break退出找到路径，continue跳过无效输入。

### 5.4 集合

编号/邮箱唯一检查使用集合视图；技能汇总使用集合。集合不负责稳定展示。

### 5.5 字典

具名字段降低位置错误。`.get` 可处理别名和计数，但关键字段不能用默认掩盖损坏。

### 5.6 JSON

对象/数组/字符串/数字/布尔/null 映射 Python。schema/version与revision分开。运行数据不进制品。

### 5.7 函数

输入参数、结构化返回、显式副作用。规范化和查询尽量纯，持久化集中，CLI编排。

## 6. 联系人核心函数解读

### 6.1 邮箱规范化

```python
value = raw_value.strip().lower()
```

一个@，本地和域名非空，域名含有效点。它不是 RFC 完整验证，也不发确认邮件。

### 6.2 新增双唯一

```python
ids = {item["contact_id"] for item in contacts}
emails = {item["email"] for item in contacts}
```

两项都通过才 append。失败返回 changed False。

### 6.3 更新邮箱

检查其他联系人：

```python
item["contact_id"] != contact_id and item["email"] == new_email
```

排除自己，否则保持同邮箱会被误判重复。

### 6.4 搜索

拼接多字段的标准展示值。子串搜索简单可解释，但“ai”可能命中 email 等非预期片段，产品需理解。

### 6.5 部门统计

```python
counts[department] = counts.get(department, 0) + 1
```

经典字典计数。最终按键排序生成稳定对象。

### 6.6 删除与复用

硬删除后编号和邮箱不在主列表，集合每次现算，因此可复用。生产历史主键通常不允许复用，当前仅模拟。

## 10. 函数单测策略

### 10.1 规范化

编号空/前缀/合法；部门别名/未知；邮箱大小写/多个@/空侧/域名点；技能多组去重。

### 10.2 工厂

姓名岗位空白折叠、skills不共享。

### 10.3 唯一性

重复编号和重复邮箱分别拒绝。

### 10.4 更新

岗位变化True、相同False、重复邮箱False、未知编号False。

### 10.5 查询

排序不改主列表；搜索姓名/部门/岗位/邮箱/技能；空关键词。

### 10.6 统计

总数、部门字典、技能集合稳定排序。

### 10.7 持久化

临时路径 revision、加载往返。

```python
def filter_by_skills(contacts, *skills, match_all=False):
    wanted = set(normalize_skills(skills))
    if not wanted:
        return []
    result = []
    for contact in contacts:
        current = set(contact["skills"])
        if match_all and wanted.issubset(current):
            result.append(contact)
        elif not match_all and wanted & current:
            result.append(contact)
    return ordered_contacts(result)
```

## 21. 周测逐题解析与错因诊断

这一节不是重复答案，而是帮助讲师根据错误判断知识缺口。学员订正必须写“原答案、错误原因、正确规则、一个新例子”。

### 21.1 `input()` 为什么始终先是字符串

键盘传来字符序列，程序无法自动知道“100”是工单量、编号还是文本。业务层明确调用 int/float 转换。错答 int 说明把字符外观当类型。

### 21.2 字符串乘法

`"100" * 2` 是重复，不是数值乘法。若学员答200，要求用 `type()` 观察并重写 `int("100") * 2`。

### 21.3 空字符串真值

空字符串为 False。不能因此把所有空容器语义混同；必填字段可显式比较，业务上 null、缺键、空字符串仍不同。

### 21.4 range 右边界

`range(1,4)` 不含4，与切片 stop 不包含一致。常见错因是按数学闭区间理解。

### 21.5 continue

只跳过当前循环本轮，不退出循环，不退出函数。与 break、return、SystemExit 对照。

### 21.6 列表与元组

可变性是主要区别，但二者都有序、可重复。说“元组安全”不完整；外层变量仍可重新绑定，且不可变不等于授权。

### 21.7 集合顺序

不能作为界面契约。即使本次运行看起来稳定，也要排序后输出。错误通常来自把观察到的现象当语言保证。

### 21.8 字典成员

`key in mapping` 检查键。检查值用 values，但通常应按键读取。联系人编号唯一集合比扫描字典值更明确。

### 21.9 null 与 None

JSON 文本 null，Python 对象 None。手写 JSON 不能用 None，Python 代码不能把 null 当名字。

### 21.10 dumps

末尾 s 表示 string，返回文本。dump 接文件对象。错答“写文件”说明混淆序列化与持久化。

### 21.11 中文序列化

`ensure_ascii=False` 影响文本可读形式，不改变 Python 字符串含义。文件还需 UTF-8。

### 21.12 隐式 None

函数无 return 或执行到结尾返回 None。print 的返回值也是 None，因此不能用 print 代替接口结果。

### 21.13 `*args`

调用中的多个位置参数收集为元组。星号也可在调用处展开序列。不能笼统回答“列表”。

### 21.14 `**kwargs`

关键字参数收集为字典。灵活性必须配白名单，尤其更新联系人字段。

### 21.15 可变默认

默认对象在 def 执行时创建并跨调用共享。None 模式在每次调用内创建新列表。要求学员画两次调用的对象引用。

### 21.16 查询副作用

原地 sort 会改变主列表。若产品要求保留录入顺序，应返回新列表。函数名 `get/search/ordered` 通常不应隐藏修改。

### 21.17 schema 与 revision

schema解释结构，revision记录数据变更。代码版本0.0.7仍可使用schema1。混淆会导致每次保存都变成未知结构。

### 21.18 哈希边界

摘要一致说明字节一致，不能证明是谁发布、是否可信。签名和受控制品库以后实现。

### 21.19 邮箱归属

格式通过只说明文本形态满足教学规则；真正归属需要验证邮件或权威身份源。目录不得把格式校验当认证。

### 21.20 JSON 与数据库

JSON缺事务、并发、查询、权限、索引和备份体系。小型单进程模拟可用，生产目录不可直接沿用。

### 21.21 引用别名

`copy = items` 不复制列表，两名字指向同对象。需要浅复制时 `items.copy()`，嵌套对象仍共享。错答不变说明不理解引用。

### 21.22 集合去重

重复 rag 只保留一个，agent 另一个，总数2。大小写不同在标准化前仍是不同字符串。

### 21.23 越界逻辑

小于1或大于5是任一端越界，用or。and 条件不可能成立。要求画数轴。

### 21.24 默认列表事故

连续调用结果累积。修复不是函数末尾 clear，而是默认None并调用内创建。

### 21.25 revision语义

每次真实写变更+1。查看、搜索、统计、失败新增和无变化更新不增加。它不是时间戳。

### 21.26 派生索引

task_ids/联系人ID集合完全来自主列表，可重建。保存派生值增加不一致风险。

### 21.27 未知schema

默认空数据会在下一次保存覆盖用户文件。正确是fail closed、保留原文、提示支持版本。

### 21.28 主入口保护

测试导入需要函数定义但不能运行input。缺保护会挂起或EOF。

### 21.29 稳定搜索结果

相同数据应有可预测顺序，便于用户、测试和审计。排序字段必须写入需求。

### 21.30 数据不入制品

制品是静态程序，联系人是环境状态。混入会泄漏和污染部署，哪怕是模拟数据也违反隔离原则。

### 21.31-40 设计题评分细则

字段字典必须包含名称、类型、必填、规则和示例；唯一验收要有 Given/When/Then 和大小写标准化；跨进程测试必须真退出；测试分层要说明定位与整体协作；global 讨论要提隐藏依赖；搜索需列五字段和空关键词；统计输出需稳定；删除风险要提审计/恢复/主键复用；模拟边界要提 `.test` 和数据最小化；流程图需包含清洗、校验、唯一、保存。每缺一核心要素扣相应分，不以篇幅评分。

提前返回空。否则空串会命中所有联系人，造成意外批量暴露。

### 22.25 更新岗位

字段变化返回True，revision+1。更新为相同岗位False，不写文件。

### 22.26 更新邮箱自己

保持原邮箱时不应被自己判重复。检查其他contact_id。

### 22.27 更新为他人邮箱

拒绝且不修改。先检查唯一再赋值。

### 22.28 kwargs未知字段

传入password或admin应忽略。安全关键接口未来应明确错误。

### 22.29 删除不存在

返回False，revision不变。

### 22.30 删除存在

pop联系人，revision+1，JSON不再包含。硬删除无审计是已知风险。

### 22.31 删除后复用

C1与旧邮箱释放，可新增新联系人。生产目录通常不允许历史编号复用，当前模拟规则。

### 22.32 部门统计

字典计数按部门键排序。两人不同部门各1。

### 22.33 技能统计

所有技能汇总集合再排序，重复只一次。

### 22.34 首进程revision

owner1、新增C2为2、新增C1为3、重复邮箱不变、更新C2为4。

### 22.35 第二进程revision

恢复4、删除C1为5、新增新C1为6。搜索/统计/退出保持6。

### 22.36 锁定

exit2，owner未保存，JSON不创建。部署脚本可据状态码判断失败。

### 22.37 schema拒绝

schema9 exit3，原文本逐字不变。不询问维护人。

### 22.38 构建冒烟

首次新增演示联系人，第二进程按agent技能搜索。证明业务闭环。

### 22.39 构建清理

删除运行JSON后，暂存目录恰好三项。缺任一或多任一都失败。

### 22.40 解压部署

首次新增审计联系人，第二进程更新岗位并搜索高级，最终JSON revision3。

## 24. 架构决策记录

### ADR-007-1：使用联系人专用JSON

状态：接受。  
决策：`nexus_contacts.json` 与任务文件分离。  
原因：不同聚合和Schema语义，避免互相覆盖。  
后果：多个文件管理，后续数据库统一。

### ADR-007-2：邮箱作为次唯一键

状态：教学接受。  
原因：演示双唯一与标准化。  
限制：邮箱可变、共享、未验证，生产身份键不能只靠邮箱。

### ADR-007-3：跨字段子串搜索

状态：MVP。  
原因：用第一周字符串和循环可实现。  
限制：无字段权重、分词、模糊、权限。  
演化：数据库全文检索、RAG/向量搜索。

### ADR-007-4：硬删除

状态：仅模拟。  
原因：练习CRUD。  
风险：无审计恢复。  
生产：软删除、离职状态、审计。

### ADR-007-5：排序字段

状态：接受。  
规则：部门、姓名、编号。  
目的：稳定输出。  
注意：Unicode顺序不等于企业组织顺序，未来配置部门序号。

### ADR-007-6：发布包无数据

状态：强制。  
任何联系人JSON即使模拟也不得进入通用制品。构建与测试双重检查。

## 25. 安全威胁建模

```mermaid
flowchart TD
    Input[用户输入] --> T1[真实个人信息误录]
    Search[目录搜索] --> T2[越权枚举]

    Build[构建] --> T6[数据进入制品]

    Controls --> C2[字段最小化]
    Controls --> C3[kwargs白名单]
    Controls --> C4[schema拒绝]
    Controls --> C5[制品白名单]
```

### 25.1 误录真实数据

界面和课件明确模拟；评审发现立即删除文件、提交和截图。真实数据不能通过“打码后继续”默认保留。

### 25.2 越权搜索

当前单机模拟无权限。生产目录必须根据身份过滤字段和范围，不能先取全量再在客户端隐藏。

### 25.3 明文JSON

不存真实数据。生产需权限、加密、备份和审计，不把密钥与数据同文件。

### 25.4 字段越权

update_contact白名单不允许contact_id/admin/password。生产还需基于操作者授权。

### 25.5 删除破坏

硬删除缺审计。生产用状态变更、审批和可恢复记录。

### 25.6 制品泄漏

构建双进程会生成JSON，必须删除。zip负向断言。CI制品也应扫描。

### 25.7 日志泄漏

当前没有日志。未来日志避免完整邮箱、搜索词和原始响应；需要脱敏和访问控制。

### 25.8 测试数据风险

示例必须明显虚构，使用 `.test`。不要从生产导出后“随机改几个字段”。

## 26. 第一周代码质量专题

### 26.1 正确性

是否符合验收，不以“没报错”为准。双唯一、排序、revision都需断言。

### 26.2 可读性

业务名称、函数职责、具名字典、决策注释。注释不复述每个符号。

### 26.3 可测试性

纯函数、显式路径、结构化返回、入口保护。避免全局可变状态。

### 26.4 可维护性

规则单一来源，失败返回稳定，Schema版本明确。重复代码进入重构。

### 26.5 安全性

数据最小化、模拟域、字段白名单、制品隔离、准确边界。

### 26.6 可部署性

标准库、README、哈希、白名单、解压冒烟、退出码。

### 26.7 可观测性

revision和明确反馈提供基础观察；生产还需结构化日志和指标。

### 26.8 不过度设计

第一周不引入数据库、Web框架或复杂模式。企业级不等于技术堆叠，而是需求、边界和证据匹配。

## 27. 缺陷案例库

1. 邮箱大小写绕过唯一：标准化前比较。  
2. 更新自己邮箱被判重复：未排除ID。  
3. 空搜索返回全部：缺空值短路。  
4. 排序测试期望写反：未按需求字段。  
5. revision失败操作增长：persist位置错误。  
6. JSON与任务文件同名：跨项目污染。  
7. 构建zip含联系人：冒烟后未删除。  
8. 导入模块启动CLI：无入口保护。  
9. 技能set直接dump：非JSON类型。  
10. 真实邮箱进Git：测试数据违规。  
11. 更新允许contact_id：主键漂移。  
12. 搜索直接输出原始输入：隐私风险。  
13. 删除后统计缓存未更新：重复状态。  
14. 未知schema默认空：数据覆盖。  
15. 同时两进程写：更新丢失。

每个缺陷写最小复现、影响、修复、回归测试和长期改进。
