# “智枢”企业级 Agent 平台：70 天贯穿式项目蓝图

## 1. 项目定位

“智枢（NexusAI）”是一家虚构但业务约束按真实企业设计的零售集团内部智能协作平台。平台服务客服、销售、财务、法务、人力资源与管理层，最终具备统一身份、企业知识库、智能问答、工具调用、流程审批、多 Agent 协作、模型接入、可观测性、安全审计和容器化部署能力。

课程不采用彼此无关的演示案例。每天都在同一个产品仓库、同一组业务角色和同一套项目管理规则上增加一段可运行能力。Day 1 的“员工信息卡片”会逐步演化为用户中心；命令行问答会演化为模型网关；本地 JSON 会演化为会话数据库；文档关键词统计会演化为 RAG 摄取流水线；函数调用会演化为工具中心；最终形成可部署的平台。

## 2. 企业背景

客户“华东智联零售集团”拥有 1,800 名员工、67 家门店和四个区域仓。现有制度、商品资料、客服话术与销售数据分散在网盘、Wiki、数据库和个人电脑中。集团提出以下目标：

1. 员工能够在一个入口查询制度、商品和业务数据。
2. 客服问题可由智能体初步分类、检索和生成答复。
3. 涉及退款、合同、邮件发送等高风险动作必须经过人工确认。
4. 所有模型调用、知识引用和工具执行必须可追溯。
5. 平台应支持模型替换，避免绑定单一供应商。
6. 试点环境可低成本运行，生产架构具备扩展路径。

## 5. 项目管理节奏

每天均执行一个压缩后的企业迭代闭环：

```mermaid
flowchart LR
    A[晨会：同步目标与风险] --> B[需求澄清：用户故事与验收标准]
    B --> C[技术设计：接口/数据/异常]
    C --> D[编码：小步提交]
    D --> E[测试：正常/边界/异常]
    E --> F[评审：代码与业务验收]
    F --> G[复盘：债务、指标、次日输入]
```

所有需求使用 `US-阶段-序号` 编号，缺陷使用 `BUG-阶段-序号` 编号，架构决策使用 `ADR-序号` 编号。每个提交都应能关联需求；任何“做完”必须同时满足代码、测试、文档和验收标准。

## 6. 课程内容的完成定义

每天课件至少包含：

- 上下文旁白：说明昨天的产物、今天为什么做、明天如何使用。
- 业务需求：角色、场景、价值、范围、验收标准和非功能约束。
- 可视化：流程图、架构图、数据结构图或交互时序图。
- 课堂笔记：概念、示例、常见错误和工程决策。
- 可运行代码：关键行有解释性注释，不使用无意义占位符。
- 测试与验收：至少覆盖正常、边界和异常路径。
- 团队协作材料：任务拆分、评审清单、风险和复盘。
- 分层作业：基础、进阶、企业挑战，并提供完整参考答案。

## 7. 代码量与质量口径

“累计 20 万行”只统计可复现仓库中的源代码、测试、基础设施即代码与教学示例，不以复制粘贴、空行或生成垃圾代码凑数。代码量是结果指标，不替代质量。最终平台还必须满足：

- 核心服务具备单元测试、集成测试与端到端测试。
- API 有契约文档，关键业务有审计记录。
- 密钥不进入版本库，敏感字段有脱敏策略。
- 失败路径可观测，重要操作可重试、可恢复或可回滚。
- 所有阶段项目均有需求文档、架构决策、测试报告和部署说明。

## 8. Day 1 的位置

Day 1 不急于调用模型。团队先交付最小的“员工信息卡片”垂直切片，用它训练需求到验收的完整闭环，并建立平台最初的数据字段。这个程序将在后续演化为身份上下文：Agent 需要依据员工姓名、部门、岗位与技能决定可访问知识、可调用工具和个性化回答方式。
